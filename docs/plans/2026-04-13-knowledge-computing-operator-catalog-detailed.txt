2. 设计原则

2.1 参数设计原则

本稿中的“参数”只写第一版关键参数，不等同于最终代码接口。参数说明遵循以下原则：

• 只列影响编排和实现边界的核心参数
• 优先列稳定业务参数，不展开底层模型/线程池等运行参数
• 优先列 DTO 级输入输出参数，不把所有内部字段都写成对外参数

2.2 实现方案分类

每个算子的实现方案统一标成以下几类：

• 复用 KAG
• 直接包装现有 KAG 组件即可
• 包装 KAG + 自研
• 底层复用 KAG，但要补业务 DTO、规则、路由或结果整理
• 复用 OpenSPG
• 主要依赖 OpenSPG 的 schema、图查询、图存储能力
• 自研
• KAG/OpenSPG 没有直接可复用能力，需要自己实现

2.3 实现优先级标记

• P0
• 必须尽快落地，支撑工作台和基础链路
• P1
• 第二批落地，支撑完整知识计算链
• P2
• 后续扩展能力

3. 顶层目录与实现侧重点

- 顶层目录：数据接入与加载；当前是否已有基础实现：部分有；主要复用来源：自研接入层、少量 KAG reader；主要新增来源：自研
- 顶层目录：数据预处理与结构化；当前是否已有基础实现：部分有；主要复用来源：KAG reader/splitter/extractor；主要新增来源：包装层
- 顶层目录：知识抽取；当前是否已有基础实现：部分有；主要复用来源：KAG extractor；主要新增来源：包装层、业务抽取规则
- 顶层目录：知识对齐与标准化；当前是否已有基础实现：很少；主要复用来源：少量现有 resolver 逻辑；主要新增来源：自研
- 顶层目录：知识融合与图构建；当前是否已有基础实现：已有较多；主要复用来源：KAG mapping/writer、OpenSPG；主要新增来源：自研融合逻辑
- 顶层目录：知识检索与召回；当前是否已有基础实现：很少；主要复用来源：OpenSPG 查询、向量召回能力；主要新增来源：自研检索编排
- 顶层目录：推理与决策生成；当前是否已有基础实现：很少；主要复用来源：OpenSPG 图查询、规则引擎；主要新增来源：自研

4. 数据接入与加载

4.1 通用基础算子

- 算子名称：pdf_source_ingest；优先级：P0；功能：接入本地文件、对象存储或上传得到的 PDF 源；第一版关键参数：source_uri, source_id, source_name, metadata, load_mode；实现方案：自研。源接入本身不是 KAG 强项，建议统一封装到我们自己的 source adapter。
- 算子名称：docx_source_ingest；优先级：P1；功能：接入 Word 文档并生成标准源对象；第一版关键参数：source_uri, source_id, source_name, metadata, load_mode；实现方案：自研。后续正文解析可复用 KAG，但接入层应统一自建。
- 算子名称：markdown_source_ingest；优先级：P0；功能：接入 Markdown 文档或文本片段；第一版关键参数：source_text/source_uri, source_id, title, metadata；实现方案：自研。接入和抽取逻辑解耦，适合作为标准入口。
- 算子名称：webpage_source_ingest；优先级：P0；功能：接入网页 URL 并记录抓取上下文；第一版关键参数：url, source_id, fetch_mode, headers, metadata；实现方案：自研。网页抓取和重试逻辑应在我们自己的接入层。
- 算子名称：rss_source_ingest；优先级：P1；功能：接入 RSS/Atom 订阅源并输出资讯记录；第一版关键参数：feed_url, source_id, poll_window, dedup_key；实现方案：自研。KAG 不负责资讯源接入。
- 算子名称：structured_table_source_ingest；优先级：P0；功能：接入 CSV/Excel/DB 行数据，转成标准结构化源；第一版关键参数：source_uri/table_name, pk_fields, field_mapping, load_mode；实现方案：自研。后续可接 KAG mapping，但接入本身仍是我们自己的职责。
- 算子名称：api_source_ingest；优先级：P1；功能：拉取第三方 API 数据源；第一版关键参数：endpoint, auth_config, pagination, retry_policy, field_mapping；实现方案：自研。偏连接器能力，不建议塞进 KAG。

4.2 业务扩展算子

- 算子名称：industry_chain_topic_load；优先级：P1；功能：按产业链专题拉取企业、产品、技术、政策等专题数据；第一版关键参数：chain_code, region_scope, time_range, data_scopes；实现方案：自研。
- 算子名称：policy_corpus_load；优先级：P1；功能：按区域/时间/主题接入政策法规语料；第一版关键参数：region_code, policy_type, time_range, source_scope；实现方案：自研。
- 算子名称：innovation_asset_load；优先级：P1；功能：加载专利、论文、成果、软著等创新链数据；第一版关键参数：asset_type, ipc_code, owner_scope, time_range；实现方案：自研。

5. 数据预处理与结构化

5.1 通用基础算子

- 算子名称：pdf_parse；优先级：P0；功能：把 PDF 源解析成标准 DocumentDTO；第一版关键参数：parse_mode, page_range, ocr_enabled, layout_enabled；实现方案：包装 KAG PDFReader。需要补 DTO 适配和异常处理。
- 算子名称：docx_parse；优先级：P1；功能：解析 docx 文档正文与标题层级；第一版关键参数：parse_mode, include_comments, extract_tables；实现方案：包装 KAG DocxReader。
- 算子名称：html_extract；优先级：P0；功能：提取网页正文、标题、发布时间、链接结构；第一版关键参数：content_selector, clean_html, keep_links；实现方案：包装 KAG 读入能力 + 自研正文提取。
- 算子名称：markdown_normalize；优先级：P0；功能：统一 Markdown 标题层级、引用块、列表结构；第一版关键参数：normalize_heading, normalize_quote, strip_empty_blocks；实现方案：包装 KAG MarkDownReader + 自研规范化。
- 算子名称：document_clean；优先级：P0；功能：清理乱码、页眉页脚、冗余空白、无效噪声；第一版关键参数：clean_rules, dedup_paragraph, remove_boilerplate；实现方案：自研。 KAG 无现成稳定清洗算子。
- 算子名称：text_chunk_split；优先级：P0；功能：按长度、语义或标题切分 chunk；第一版关键参数：split_mode, chunk_size, overlap, heading_aware；实现方案：包装 KAG LengthSplitter/SemanticSplitter/OutlineSplitter。
- 算子名称：outline_extract；优先级：P1；功能：提取章节和段落层级结构；第一版关键参数：max_depth, preserve_section_id；实现方案：包装 KAG OutlineExtractor。
- 算子名称：table_extract；优先级：P1；功能：从文档中抽取表格块及表格上下文；第一版关键参数：table_mode, keep_context, max_cells；实现方案：包装 KAG TableExtractor。
- 算子名称：format_normalize；优先级：P1；功能：统一日期、金额、编码、标点等文本格式；第一版关键参数：date_format, currency_format, normalize_punctuation；实现方案：自研。

5.2 业务扩展算子

- 算子名称：industry_document_parse；优先级：P1；功能：识别产业文档类型并恢复章节逻辑；第一版关键参数：doc_type_hint, section_schema, extract_appendix；实现方案：包装通用解析算子 + 自研规则。
- 算子名称：patent_fulltext_preprocess；优先级：P1；功能：专利全文拆成摘要、权利要求、说明书等模块；第一版关键参数：split_claims, split_description, drop_legal_notice；实现方案：自研。专利文本结构有明显业务特性。
- 算子名称：policy_text_normalize；优先级：P1；功能：标准化政策文本层级、文号、有效期等信息；第一版关键参数：extract_doc_no, extract_effective_date, clause_mode；实现方案：自研。
- 算子名称：announcement_normalize；优先级：P1；功能：清洗企业公告、招投标公告等文本；第一版关键参数：announcement_type, drop_risk_note, extract_subject；实现方案：自研。
- 算子名称：industry_code_normalize；优先级：P1；功能：标准化 IPC、ICD、行业代码、区域码等；第一版关键参数：code_system, version, strict_validate；实现方案：自研。

6. 知识抽取

6.1 通用基础算子

- 算子名称：entity_extract；优先级：P0；功能：从 chunk 中抽实体候选；第一版关键参数：schema_ref, entity_types, llm_profile, confidence_threshold；实现方案：包装 KAG schema_constraint_extractor.named_entity_recognition。
- 算子名称：entity_standardize；优先级：P0；功能：对抽出的实体做标准化和别名归并；第一版关键参数：schema_ref, normalize_mode, official_name_enabled；实现方案：包装 KAG schema_constraint_extractor.named_entity_standardization，并补业务别名策略。
- 算子名称：relation_extract；优先级：P0；功能：从文本中抽关系候选；第一版关键参数：schema_ref, relation_types, llm_profile, confidence_threshold；实现方案：包装 KAG schema_constraint_extractor.relations_extraction。
- 算子名称：event_extract；优先级：P0；功能：从文本中抽事件候选；第一版关键参数：schema_ref, event_types, time_extraction, location_extraction；实现方案：包装 KAG schema_constraint_extractor.event_extraction。
- 算子名称：concept_seed_extract；优先级：P1；功能：从文本中抽概念候选或概念归属；第一版关键参数：concept_types, schema_ref, mode；实现方案：包装 KAG 抽取结果 + 自研概念候选整理。
- 算子名称：table_fact_extract；优先级：P1；功能：从表格 seed 中抽结构化事实；第一版关键参数：fact_schema, header_mode, merge_cells；实现方案：包装 KAG TableExtractor 结果并二次整理。
- 算子名称：summary_extract；优先级：P2；功能：提取 chunk 或文档摘要，用于后续检索与解释；第一版关键参数：summary_length, style, schema_hint；实现方案：包装 KAG SummaryExtractor。

- 算子名称：enterprise_capability_extract；优先级：P1；功能：抽企业科创能力、制造能力、平台能力等；第一版关键参数：capability_schema, dimension_set, score_hint；实现方案：包装通用抽取 + 自研业务规则。

9. 知识检索与召回

9.1 通用基础算子

- 算子名称：vector_retrieve；优先级：P1；功能：向量语义检索 chunk、摘要或知识单元；第一版关键参数：query, top_k, similarity_threshold, index_name；实现方案：包装现有向量检索能力，KAG 可部分复用，整体编排需自研。
- 算子名称：graph_retrieve；优先级：P1；功能：按实体、关系、属性或路径做图谱精确检索；第一版关键参数：query_pattern, entity_type, relation_type, limit；实现方案：复用 OpenSPG 图查询能力，包装成算子。
- 算子名称：hybrid_retrieve；优先级：P1；功能：混合向量检索、图检索、关键词检索结果；第一版关键参数：query, top_k, weights, rerank_strategy；实现方案：自研编排层，底层复用多种检索能力。

• 所有 source ingest 连接器

• 业务推理

这些是业务平台能力，不是 KAG 通用组件能力。

14. 落地建议

14.1 当前仓库内的建议组织方式

建议继续沿用当前仓库组织，但逐步把：

• knowledge_extraction_operators

演进成更明确的“知识计算算子层”。短期内不强制改目录路径，避免一次性迁移过大。

14.2 与 KAG/OpenSPG 的分工

• KAG
• 通用 builder component
• OpenSPG
• schema、图谱存储、图谱查询
• 我们自己的算子层
• DTO、registry、runtime、业务扩展算子、工作台、pipeline 编排

14.3 核心实现原则

1. 能包装 KAG 的，不重复造轮子
2. 业务逻辑不回写进 KAG 本体
3. 工作台始终面向“知识计算目录”而不是“内部实现分层”
4. 实现优先级始终以 P0/P1 为主，不追求一次性铺满全目录

15. 最终建议

最终建议可以收敛成一句话：

后续实现时，先按 7 类知识计算目录来组织算子，用“通用基础 / 业务扩展”作为第二维，并优先包装 KAG 的通用组件；凡是涉及实体归一、多源融合、产业专题检索和业务推理的部分，统一放在我们自己的知识计算算子层实现。
