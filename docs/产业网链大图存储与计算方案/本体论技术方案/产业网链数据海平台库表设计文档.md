>
> ```sql
> SELECT d.type_name, COUNT(r.resource_doc_id) as doc_count
> FROM inc_data_type_dict d
> LEFT JOIN resource_* r ON r.resource_type = d.type_code
> WHERE d.status = 'active'
> GROUP BY d.type_code
> ORDER BY d.sort_order;
> ```

### 1.4 MongoDB 原始资源集合（resource\_\<资源类型\>\_\<数据来源\>）

> 说明：资源层贴合原始数据（raw\_document 概念），不同原始数据格式不强行统一。集合命名严格遵循 `resource_<资源类型>_<数据来源>`（如 `resource_news_baidu`、`resource_report_ths`）。存储介质为 MongoDB；含大字段（raw\_content/raw\_html 等）集合按 `data_source + crawl_time` 分片存储，均衡写入压力。保留 `process_batch_id`、`resource_doc_id`、`status` 等关键字段，支撑批量加工与全链路溯源。

**MongoDB 分片策略说明**：
- 分片键：`{ data_source: 1, crawl_time: 1 }`（复合分片键）
- 分片策略：Range 分片，按数据源 + 时间范围自动分裂
- 分片粒度：单个 Chunk 目标大小 64MB，超过后自动拆分
- 适用场景：按数据源批量查询、按时间范围扫描

## 2. 数据要素层（三库分节）

### 2.1 全局编码规范（跨层通用）

> 说明：全局编码采用统一格式 `<前缀><数字序列>`，**不使用下划线分隔**，确保格式一致性。所有 ID 均为纯字符串，便于跨系统传递与索引。

| 数据源ID       | DS  | 12位 | DS0000000001           | 资源层/要素层 |
| 实体ID        | EN  | 18位 | EN0000000000000001     | 知识网络/图谱 |
| Statement主键 | ST  | 18位 | ST0000000000000001     | 知识网络    |
| ContextID   | KC  | 18位 | KC0000000000000001     | 知识网络    |
| 图谱边ID       | ED  | 18位 | ED0000000000000001     | 图谱库     |

### 2.2 本体模型（规范层）

> 说明：本体模型采用 MySQL 等关系型元数据库，后续可服务化对外提供语义规范与映射规则；建议库名 `ontology_schema_registry`。存储引擎统一使用 MySQL，为规范层提供强一致性保障。

#### 2.2.1 本体类定义（inc\_ontology\_classes）

```sql
CREATE TABLE inc_ontology_classes (
  id VARCHAR(14) PRIMARY KEY COMMENT '本体类ID（格式：OC + 12位数字）',
  name VARCHAR(128) NOT NULL COMMENT '本体类名称',
  name_en VARCHAR(128) COMMENT '本体类英文名',
  description TEXT COMMENT '本体类描述',
  parent_class_id VARCHAR(14) COMMENT '父类ID', 
  -- 五维分类标识
  entity_category ENUM('concept','actor','event','element','space','time','type') NOT NULL COMMENT '本体模型门类：概念/主体/事件/要素、对象/空间/时间/类型',
  layer ENUM('core','domain','application') DEFAULT 'domain' COMMENT '分层级别',
  status ENUM('draft','active','deprecated') DEFAULT 'active' COMMENT '状态',
  version INT DEFAULT 1 COMMENT '版本号',
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',

  INDEX idx_parent (parent_class_id),
  INDEX idx_layer (layer),
  INDEX idx_status (status),
  INDEX idx_category (entity_category)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='本体类定义表';
```

> **五维分类说明**：
> - `concept`：概念类，如"产业链"、"技术领域"等抽象概念
>
>> - `actor`：主体类，如"企业"、"机构"、"人物"等行为主体
>> - `element`：要素类，如"产品"、"技术"、"专利"等产业要素
>> - `event`：事件类，如"投融资"、"上市"、"合作"等动态事件
>> - `space`：空间类，如"国家"、"详细地址"、"区域"等空间位置信息
>> - `time`：时间类，如"日期"、"事件跨度"等时间点或时间范围
>> - `type`：类型类，如"产品类型"、"企业类型"等分类标签

#### 2.2.6 一阶段语义映射规则（inc\_mapping\_rules）

> 用于把当前库表字段映射为 SPG 语义单元。该表是一阶段核心，不要求立即重构业务表，只要求显式声明“从哪里来、转成什么语义、怎么校验”。

```sql
CREATE TABLE inc_mapping_rules (
  rule_id VARCHAR(18) PRIMARY KEY COMMENT '映射规则ID（格式：MR + 16位数字）',
  rule_name VARCHAR(128) NOT NULL COMMENT '规则名称',
  source_system VARCHAR(64) NOT NULL COMMENT '来源系统（resource/ods/dwd/api等）',
  source_object VARCHAR(128) NOT NULL COMMENT '来源对象（表/集合/接口）',
  source_path VARCHAR(256) NOT NULL COMMENT '来源字段路径（支持JSONPath）',
  transform_expr TEXT COMMENT '转换表达式（SQL/DSL/函数名）',
  target_class_id VARCHAR(14) NOT NULL COMMENT '目标本体类ID',
  target_predicate_id VARCHAR(14) COMMENT '目标谓词ID（属性或关系）',
  target_slot ENUM('entity_name','property_value','relation_object','context_time','context_evidence') NOT NULL COMMENT '目标槽位',
  assertion_mode ENUM('fact','candidate','inferred') DEFAULT 'fact' COMMENT '写入模式',
  quality_gate JSON COMMENT '质量门禁（必填率/唯一性/阈值）',
  effective_from DATETIME COMMENT '生效时间',
  effective_to DATETIME COMMENT '失效时间',
  status ENUM('draft','active','deprecated') DEFAULT 'active' COMMENT '状态',
  version INT DEFAULT 1 COMMENT '版本号',
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',

  INDEX idx_source (source_system, source_object),
  INDEX idx_target_class (target_class_id),
  INDEX idx_target_predicate (target_predicate_id),
  INDEX idx_status (status)
```

### 2.3 知识网络（实例层）

> 说明：知识网络数据量大，当前优先 MongoDB + Neo4j，未来演进 HBase + GalaxyBase；建议库名 `knowledge_network`。知识网络由四大核心集合组成：**micro_document（微文档）**、**entity（实体）**、**context（上下文）**、**statement（事实三元组）**。standard_document（标准文档）归属资源层，micro_document 通过 `doc_id` 关联标准文档。下列表为逻辑字段规范，同时提供 SQL DDL（用于 MySQL 轻量部署）和 MongoDB Schema（用于生产环境）。

#### 2.3.6 事实Statement（statement）

> **Statement 三类语句说明**：
> - `type`：**类型语句（实体归属类）** - 表达实体属于哪个本体类，如"华为 是 企业"
> - `property`：**属性语句（实体特征）** - 表达实体的数据属性值，如"华为 成立日期 1987-09-15"
> - `relation`：**关系语句（实体关联）** - 表达实体间的对象关系，如"华为 投资 海思半导体"

```sql
CREATE TABLE inc_statement (
  statement_id VARCHAR(18) PRIMARY KEY COMMENT 'Statement全局唯一ID（格式：ST + 16位数字）',
  statement_hash VARCHAR(64) NOT NULL COMMENT '幂等哈希（见下方计算规则）',
  assertion_mode ENUM('fact','candidate','inferred') DEFAULT 'fact' COMMENT '断言模式：事实/候选/推理',
  -- Statement 三类语句
  statement_type ENUM('type','property','relation') NOT NULL COMMENT '语句类型：type(实体归属类)/property(实体特征)/relation(实体关联)',
  subject_id VARCHAR(18) NOT NULL COMMENT '主体实体ID',
  predicate_id VARCHAR(14) COMMENT '属性/关系ID（type语句时为NULL，property关联inc_property_definitions，relation关联inc_relation_types）',
  object_type ENUM('class','entity','literal') NOT NULL COMMENT '客体类型：class(本体类)/entity(实体)/literal(字面量)',
  object_class_id VARCHAR(14) COMMENT '客体本体类ID（当statement_type=type时）',
  object_entity_id VARCHAR(18) COMMENT '客体实体ID（当object_type=entity时）',
  object_value TEXT COMMENT '客体字面量值（当object_type=literal时）',
  object_value_type ENUM('string','integer','decimal','boolean','date','datetime','json') COMMENT '字面量值类型',
  context_id VARCHAR(18) NOT NULL COMMENT '上下文ID（关联inc_context）',
  confidence DECIMAL(5,4) DEFAULT 1.0 COMMENT '置信度',
  crystallized BOOLEAN DEFAULT FALSE COMMENT '结晶标识（高置信度已验证）',
  rule_id VARCHAR(64) COMMENT '推导规则ID（assertion_mode=inferred时必填）',
  derivation_path JSON COMMENT '推导链路（可解释路径）',
  engine_run_id VARCHAR(64) COMMENT '执行引擎运行ID（关联inc_task_runs.run_id）',
  -- 版本管理
  version INT DEFAULT 1 COMMENT '版本号',
  previous_version_id VARCHAR(18) COMMENT '前序版本Statement ID',
  change_reason VARCHAR(256) COMMENT '变更原因',
  status ENUM('active','deprecated') DEFAULT 'active' COMMENT '状态',
  process_batch_id VARCHAR(64) COMMENT '加工批次ID',
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',

  UNIQUE KEY uk_statement_hash (statement_hash),
  INDEX idx_assertion_mode (assertion_mode),
  -- 按语句类型查询
  INDEX idx_statement_type (statement_type, subject_id),
  -- 正向查询：以实体为主体
  INDEX idx_spo (subject_id, predicate_id, object_type),
  -- 反向查询：以实体为客体（查某实体被哪些Statement引用）
  INDEX idx_ops (object_entity_id, predicate_id, subject_id),
  -- 类型语句查询：查实体属于哪些类

  INDEX idx_batch_status (process_batch_id, status),

```

> **Statement 三类语句使用规则**：
>
> | statement_type |   predicate_id    | object_type |              示例               |
> |----------------|-------------------|-------------|-------------------------------|
> | `type`         | NULL（隐含 rdf:type） | `class`     | 华为 → 企业（EN001 rdf:type OC001） |
> | `property`     | 属性定义ID（PD...）     | `literal`   | 华为 成立日期 1987-09-15            |
> | `relation`     | 关系类型ID（RT...）     | `entity`    | 华为 投资 海思（EN001 RT001 EN002）   |
>
> **Statement Hash 计算规则**：
>
> ```
> statement_hash = SHA256(
>   statement_type + "|" +
>   subject_id + "|" +
>   COALESCE(predicate_id, "rdf:type") + "|" +
>   object_type + "|" +
>   COALESCE(object_class_id, object_entity_id, object_value) + "|" +
>   context.begin_time（ISO8601格式，如无则为"NULL"）
> )
> ```
>
> - 使用 `|` 作为分隔符，避免字段值拼接碰撞
> - `context.begin_time` 作为时态键，区分同一事实在不同时间点的取值
> - 示例：`SHA256("property|EN0000000000000001|PD000000000001|literal|1000000|2026-01-30T00:00:00Z")`

### 4.1 ER Diagram 解读

该图展示了产业网链数据海平台的三层架构及其表间关系：

#### 4.1.1 数据资源层（最上层）

**数据采集链路：**

```
ds_basic_info → ds_access_task → ds_access_record
   (数据源)        (接入任务)        (执行记录)
```

- `ds_basic_info` 定义数据源基础信息（如官网、API等）
- `ds_access_task` 配置该数据源的采集任务（全量/增量/实时）
- `ds_access_record` 记录每次采集执行的结果与统计

**数据存储链路：**

```
ds_basic_info → minio_file_index ← resource_* → inc_document → inc_microcontent
                   (文件索引)       (原始资源)    (标准化文档)     (微文档)
```

- `minio_file_index`：MinIO 文件的元数据索引，通过内容哈希去重
- `resource_*`：按类型/来源命名的原始资源集合（如 `resource_news_baidu`）
- `inc_document`：经标准化处理后的文档，含向量嵌入
- `inc_microcontent`：文档中的语义片段（句子/短语），支撑事实抽取溯源

#### 4.1.2 数据要素层（中间层，核心）

**本体模型库（MySQL，规范层）：**

```
inc_ontology_classes ◀──▶ inc_property_definitions
      (本体类)                  (属性定义)
         │
         ▼
inc_ontology_activities      inc_relation_types
    (动作规则)                  (关系类型)
```

- 定义"企业"、"产品"等本体类及其属性/关系的语义规范
- 五维分类：概念(concept)、主体(subject)、要素(element)、事件(event)、文档(document)

**实例知识库（MongoDB/MySQL，实例层）：**

```
entity_instances → entity_aliases      entity_core_properties
   (实体实例)        (实体别名)            (核心属性-单值)
         │
         │ entity_id
         ▼
  inc_statement ────→ inc_context ◀── doc_id ◀── inc_document
   (事实三元组)         (上下文)    ◀── micro_document_id ◀── inc_microcontent
```

**关键关联：**

|                                    关联路径                                    |     说明      |
|----------------------------------------------------------------------------|-------------|
| `entity_instances.class_id` → `inc_ontology_classes.id`                    | 实体归属本体类     |
| `inc_statement.subject_id/object_entity_id` → `entity_instances.entity_id` | 三元组主客体      |
| `inc_statement.context_id` → `inc_context.context_id`                      | 事实的时间/证据上下文 |
| `inc_context.doc_id/micro_document_id` → 资源层文档                             | 溯源到原始数据     |

**主题数仓（Doris，分析层）：**

```
entity_id_mappings → dwd_entity_fact ← indicator_dictionary
   (ID映射)            (明细事实表)        (指标字典)
                                               │
                                               ▼
                                     indicator_ontology_mappings
                                        (指标-本体映射)
```

- 将外部系统主键映射到平台实体ID
- 指标字典定义业务指标口径，并与本体属性关联

**其他存储：**

|       存储组件       |             说明              |
|------------------|-----------------------------|
| 图谱库(Neo4j)       | 节点=实体实例，边=关系Statement       |
| 向量库(Milvus)      | 实体/Statement/文档的向量嵌入，支持语义检索 |
| confidence_rules | 置信度计算规则                     |

#### 4.1.3 数据服务层（最下层）

```
Elasticsearch（全文检索） + Redis Cache（热点缓存） + API Gateway（服务编排）
```

- ES 索引：entity_index、statement_index、document_index
- Redis：实体详情、Statement集合、本体缓存等
- API Gateway：统一鉴权、多源查询编排

#### 4.1.4 核心数据流向总结

```
原始数据 → 资源层(采集/存储) → 标准化文档 → 知识抽取 → 实例知识库(Statement)
                                              ↓
                              本体模型库(语义规范) ← 约束校验
                                              ↓
                              图谱库/向量库/数仓 → 服务层(检索/分析)
```

## 5. 迭代说明

* **轻量闭环阶段（本版）**：聚焦资源层接入、语义对齐、知识库/数仓/图谱/向量最小可用，服务层提供基础检索与编排。

* **迭代扩展方向**：

  * 公理系统与规则引擎落地；

  * 产业节点多链嵌入与链路角色表达；

  * 质量规则与一致性校验自动化增强。
