产业网链体系下知识库数据资源层数据库表设计文档
1 文档概述
1.1 文档目的
本文档针对产业网链体系下知识库数据资源层，明确数据源管理、数据存储相关数据库表的设计规范、结构定义、字段说明及关联关系。旨在为数据资源层的建设提供清晰的表结构指引，保障数据源可追溯、数据存储有序化，支撑知识库与本体模型库、主题数仓的协同联动，满足产业网链数据采集、整合、管理及应用的全流程需求。
1.2 设计范围
设计范围覆盖知识库数据资源层两大核心模块：一是数据源管理模块，涵盖各类接入数据源的基础信息、接入配置、质量校验等相关表；二是数据存储模块，适配半结构化文档存储（MongoDB）、文件存储（MinIO）、关系表存储（Doris、MySQL）多存储形态，设计对应的数据关联、属性映射、文件索引等支撑表。
1.3 设计依据
1. 产业网链体系“本体模型库+实例知识库+主题数仓”三位一体架构设计要求；
2. 知识库多源接入规范（含互联网采集、文件导入、API接口、前置数据库、填报等接入方式）；
3. 数据存储选型要求（MongoDB适配半结构化文档、MinIO适配文件存储、Doris/MySQL适配结构化关系数据）；
4. 产业网链数据资源管理相关业务需求（数据源追溯、数据质量管控、存储资源调度等）。
2 核心设计原则
1. 多存储适配原则：针对不同存储形态设计差异化表结构，关系型表适配MySQL/Doris，半结构化索引表适配MongoDB，文件索引表关联MinIO存储资源；
2. 可追溯性原则：通过数据源ID、数据唯一标识等字段，实现数据从接入到存储全链路的溯源；
3. 扩展性原则：表结构预留字段扩展位，适配后续产业网链新增数据源类型、数据属性及业务场景；
4. 性能优化原则：合理设计主键、索引字段，减少多表关联冗余，提升数据查询、更新效率。
3 数据源管理模块表设计
数据源管理模块核心目标是实现对多源数据接入的全生命周期管理，包括数据源基础信息登记、接入任务配置、接入执行过程记录等。本模块所有表均适配MongoDB存储（集合名统一前缀为“ds_”），涉及集合包括：数据源基础信息集合、数据接入任务集合、接入执行记录集合。
3.1 数据源基础信息集合（ds_basic_info）
3.1.1 集合说明
存储所有接入知识库的数据源基础信息，作为数据源追溯的核心关联集合，支撑数据源分类管理、负责人定位、数据质量评估等功能。适配存储：MongoDB（集合名：ds_basic_info）。
3.1.2 集合结构（JSON格式，MongoDB字段定义）
ds_basic_info
{
"_id": "ObjectId(自动生成)",  // MongoDB默认主键
"ds_id": "String(64)",        // 数据源ID，数据源唯一标识，格式：DS_接入方式_年份_序列号（如DS_API_2025_001），非空
"name": "String(128)",        // 数据源名，需准确描述数据源主体（如“国家产业政策官网”“某企业ERP系统”），非空
"description": "String(3000)",        // 数据源简介，简单介绍数据源和包含数据
"credibility_score": "Decimal(5,2)",  // 数据源数据质量评分，计算规则参考接入执行记录的质量统计结果，满分100分，非空
"metadata": "Object",         // 数据源附属信息，JSON格式便于后续扩展，非空
"ds_type": "String(32)",      // 数据源类型，枚举值：INTERNET(互联网采集)、FILE(文件导入)、API(API接口)、PRE_DB(前置数据库)、FILL(填报)，非空
"data_category": "String(64)",// 数据分类，关联本体模型库类标识，如“企业信息”“产业政策”，非空
"ds_source": "String(255)",   // 数据源具体来源，如互联网采集填URL、API填接口地址，非空
"responsible_person": "String(32)", // 责任人姓名，非空
"create_time": "Date",        // 数据源登记时间，默认当前时间，非空
"update_time": "Date",        // 数据源信息更新时间，默认当前时间，非空
"is_valid": "Boolean"         // 数据源是否有效，默认true，非空
}

metadata字段示例：
{
"description": "国家工业和信息化部发布的产业政策信息数据源，涵盖制造业、信息技术等领域政策文件",

"coverage_area": "全国",

3.2 数据接入任务集合（ds_access_task）
3.2.1 集合说明
存储不同类型数据源的具体接入任务配置信息，与数据源基础信息集合通过ds_id关联（多对一关系），支撑数据接入的自动化配置、调度与执行。适配存储：MongoDB（集合名：ds_access_task）。
3.2.2 集合结构（JSON格式，MongoDB字段定义）
ds_access_task
{
"_id": "ObjectId(自动生成)",  // MongoDB默认主键
"task_id": "String(64)",      // 任务唯一标识，格式：TASK_数据源ID_序列号，非空
"ds_id": "String(64)",        // 数据源ID，关联ds_basic_info.ds_id，非空
"task_name": "String(128)",   // 任务名称，描述接入任务核心目标，如“国家产业政策官网每日增量采集”，非空
"access_mode": "String(32)",  // 接入模式，枚举值：FULL(全量接入)、INCREMENT(增量接入)、REAL_TIME(实时接入)，非空
"priority": "int",  // 任务优先级，值越小优先级越高，0为实时任务；非空
"schedule_config": "String(128)",  // 调度配置，全量/增量接入时填写cron表达式（如0 0 1 * * ? 表示每日凌晨1点），实时接入填“REAL_TIME”
"access_params": "Object",    // 接入参数，JSON格式存储，不同数据源、不同类型接入任务，参数不同，如爬虫采集任务百度搜索数据源参数配置搜索关键词、爬虫采集任务新浪财经新闻参数配置采集页数、API接入任务配置特定数据源需要的API调用参数、前置库接入任务配置前置库连接信息数据筛选参数
"storage_config": {           // 目标存储配置，嵌套JSON对象，非空
"storage_type": "String(32)",  // 目标存储类型，枚举值：MONGO(半结构化文档存储)、MINIO(文件存储)、MYSQL(关系表存储)、DORIS(分析型关系表存储)
"storage_addr": "String(255)"  // 目标存储地址，如MongoDB集合名、MinIO桶名
},
"remark": "text",             // 备注
"is_valid": "Boolean",        // 任务是否有效，默认true，非空
"create_time": "Date",        // 任务创建时间，默认当前时间，非空
"update_time": "Date"         // 任务更新时间，默认当前时间，非空
}
3.3 接入执行记录集合（ds_access_record）
3.3.1 集合说明
存储每个接入任务每次执行过程中的详细记录，包括执行状态、数据量统计、质量校验结果等，与数据接入任务集合通过task_id关联（多对一关系），支撑任务执行追溯、数据质量排查与数据源质量评分更新。适配存储：MongoDB（集合名：ds_access_record）。
3.3.2 集合结构（JSON格式，MongoDB字段定义）
{
"_id": "ObjectId(自动生成)",  // MongoDB默认主键
"record_id": "String(64)",    // 执行记录唯一标识，格式：RECORD_任务ID_执行时间戳，非空
"task_id": "String(64)",      // 任务ID，关联ds_access_task.task_id，非空
"ds_id": "String(64)",        // 数据源ID，关联ds_basic_info.ds_id，冗余字段便于快速查询，非空
"exec_status": "String(32)",  // 执行状态，枚举值：RUNNING(执行中)、SUCCESS(执行成功)、FAILED(执行失败)，非空
"total_count": "Number(Long)",  // 本次接入总数据量，默认0
"valid_count": "Number(Long)",  // 校验通过的数据量，默认0
"invalid_count": "Number(Long)", // 校验失败的数据量，默认0
"start_time": "Date",       // 接入开始时间
"end_time": "Date",         // 接入结束时间
"exec_time": "Number(Int)",   // 执行时长，单位：秒
"error_msg": "String(255)",   // 错误信息，执行失败时填写具体原因
}
数据源管理模块核心目标是实现对多源数据接入的全生命周期管理，包括数据源基础信息登记、接入配置管理、数据质量校验记录、数据源状态监控等。涉及表包括：数据源基础信息表、数据源接入配置表、数据接入质量校验表、数据源状态监控表。
4 数据存储模块表设计
数据存储模块核心目标是适配多存储形态，实现知识库数据的有序存储与高效关联，支撑半结构化文档、文件资源、结构化关系数据的管理需求。涉及表包括：MongoDB半结构化文档索引表、MinIO文件资源索引表、MySQL/Doris结构化属性表、数据关联关系表。
4.1 MongoDB半结构化文档索引库表
4.1.1 分库说明
接入数据按数据主题不同在monggo中可分成不同的库存储数据，原则上每个数据源接入任务获取的数据格式不一致需要单独设置数据接入存储集合，实践中对于爬虫采集任务同类主题数据采集的数据格式有时十分相近也可放到统一的数据集合中，此时可设置一个通用的数据接入存储集合。
存储MongoDB中半结构化文档的核心索引信息，实现文档的快速定位与溯源，避免直接查询MongoDB全量文档的性能损耗。适配存储：MongoDB。
