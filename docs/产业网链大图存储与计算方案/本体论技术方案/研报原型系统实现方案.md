# 研报原型系统实现方案

## 1. 方案定位与范围

本方案用于在“产业网链数据海平台三层架构”与“三库分层”的统一框架下，复用现有文档处理管道，完成**研报文本知识抽取**的原型验证。覆盖全流程：接入（文件/网页）→ 清洗与去重 → 语义抽取与本体对齐 → Entity/Statement/Context 沉淀 → 图谱/向量/检索输出 → 反馈闭环。

核心目标：
1) 用研报作为文档样例验证“规范—实例—分析”闭环；
2) 在不破坏现有系统的前提下，扩展文档处理管道能力，满足研报结构化需求；
3) 明确与库表设计的一致点、差距点，并对改造项进行标注；
4) 形成可执行的原型验证清单与验收标准。

---

## 2. 总体架构与三库映射

研报方案严格沿用三层架构，并将三库落位于数据要素层：
- **本体模型库**输出语义规范与映射规则；
- **实例知识库**承载 Entity/Statement/Context，派生图谱与向量索引；
- **主题数仓**承载结构化指标与维度，指标口径与本体属性对齐。

在“文档处理管道”层面，研报属于 `document_pipeline` 的一个类型实例，与资讯共享同一处理框架，仅在解析、抽取与指标入仓策略上增强。

## 2.1 与数据海平台架构的兼容

### 2.1.1 契合性——与平台设计及代码结构对齐

本方案与《产业网链数据海平台架构设计文档》保持一致，并在现有代码结构上可直接对接：
- **三层架构一致**：资源层→要素层→服务层分层与数据流一致；
- **三库分工一致**：本体模型库负责语义规范，实例知识库承载事实，主题数仓承载指标；
- **统一ID与溯源一致**：`DS/EN/ST/KC/DOC/MC` 编码规范与 `resource_doc_id / resource_file_id / doc_id / statement_id / context_id` 贯穿链路；
- **语义映射一致**：抽取结果通过本体映射驱动进入 `inc_statement/inc_context`；
- **服务输出一致**：ES/图谱/向量索引作为服务层输出，与平台既有检索编排兼容。

与现有系统实现的对齐点（代码层面示例）：
- **资源接入与落库**：`backend/app/ingestion/*`、`backend/app/processing/*` 负责接入与清洗，对接 `resource_*` 与 `inc_document` 规范；
- **文档管道与抽取**：`backend/app/news_pipeline/*` 已实现“文档处理管道”雏形，研报仅需作为新类型实例接入；
- **语义映射与落库**：`backend/app/news_pipeline/service.py` 的抽取与对齐逻辑可复用，输出 `inc_statement/inc_context`；
- **索引与服务输出**：`backend/app/api/*` 与索引服务复用既有接口能力。

### 2.1.2 研报的特殊性与新增设计

**差异1：研报为长文档且结构化明显**  
**新增设计（实现方案）**：  
- **解析层**：在 `backend/app/processing/*` 增加“章节解析器”，输出统一的 `sections` 结构（标题、层级、页码、正文）；  
- **标准化层**：在 `inc_document.extra_meta` 写入章节目录（如 `sections: [{title, level, page_start, page_end}]`）；  
- **微内容切片**：在 `backend/app/news_pipeline/service.py` 或对应文档管道中新增 `section_based_chunker`，按章节/段落生成 `inc_microcontent`，并附带 `source_position.page/section_title`；  
- **落库约束**：每条微内容必须关联 `doc_id`，保持与 `inc_document` 追溯一致。

**差异2：定量指标密度高，含预测信息**  
**新增设计实现方案**：  
- **抽取层**：在抽取模板中增加“指标-数值-单位-周期”四元组抽取（支持 `2026E`、`2027E` 等预测表达）；  
- **标准化层**：在 `inc_document.extra_meta` 中保留“指标表格文本”的解析结果（如 `tables_text`）；  
- **入仓层**：扩展 `dwd_entity_fact` 的写入逻辑，新增 `forecast_horizon`（或写入 `extra_context`），并在 `indicator_dictionary` 中标注预测类指标；  
- **映射层**：`indicator_ontology_mappings` 加入预测期规则（如 `mapping_rule` 中包含 `forecast_horizon` 条件）。

**差异3：时间维度复杂（报告期/预测期/区间）**  
**新增设计实现方案**：  
- **时间解析**：增加统一的“时间规范化模块”，将“报告期/预测期/区间”规范为 `begin_time/end_time/time_type`；  
- **Context 落库**：在 `inc_context` 中严格使用 `time_type=interval/point/ongoing`，并保留 `extra_context` 中的“预测口径/基准期”；  
- **Statement 幂等**：时间维度纳入 `statement_hash` 计算逻辑，避免同一事实不同时间被误判重复。

**差异4：研报语义更专业（评级、目标价、估值方法、关键假设）**  
**新增设计实现方案**：  
- **文档元数据**：在 `inc_document.extra_meta` 写入 `institution/analyst/rating/target_price/valuation_method/key_assumptions`；  
- **本体扩展**：在 `inc_ontology_classes/inc_property_definitions/inc_relation_types` 中新增 `ResearchReport` 及其属性关系；  
- **抽取映射**：将评级/目标价等映射为 `inc_statement`（属性类 Statement），同时将研报-机构/作者关系写入关系类 Statement。

**差异5：PDF/扫描件文本化需求**  
**新增设计实现方案**：  
- **解析流程**：优先读取 PDF 文字层；若无文字层则调用 OCR，输出纯文本；  
- **质量标识**：在 `inc_document.extra_meta` 中记录 `ocr_used=true/false` 与 `ocr_confidence`；  
- **落库一致性**：所有文本化结果统一写入 `standard_content`，保证下游逻辑不分支。

> 说明：`inc_document` 为 MongoDB 集合，`extra_meta` 作为扩展字段用于研报特有元数据存储，不影响主结构一致性。

## 2.2 文档输入类型的泛化性

### 2.2.1 标准化文件层设计

系统已设计统一标准化文件层：原始资源 → `inc_document` → `inc_microcontent`。研报接入时：
- 原始研报进入 `resource_report_<source>` 与 `minio_file_index`；
- 文本化与清洗后统一写入 `inc_document`，标记 `resource_type=report`；
- 研报特有字段写入扩展字段（如 `institution/analyst/rating/target_price/report_date/forecast_horizon`）；
- 统一进入微内容切片与抽取链路，保证与资讯一致。

结论：标准化文件层是通用入口，研报只需扩展解析策略与元数据字段即可匹配。知识网络实例层对应 `standard_document / micro_document`，由 `inc_document / inc_microcontent` 派生并保持 `doc_id` 一致。

### 2.2.2 统一抽取、对齐与入仓

除标准化层外，泛化性还体现在：
- **统一抽取与对齐链路**：抽取→本体对齐→Statement/Context 落库为统一流程；
- **差异仅限解析与元数据**：不同文档类型仅在解析与扩展字段有差异，不改变核心结构；
- **统一指标入仓机制**：可量化信息通过 `indicator_dictionary` 与本体属性映射入仓。

因此，研报方案不仅适用于研报场景，也能作为“文档处理管道”的通用模板扩展到其他类型文档。

## 3. 研报接入标准化文件层

研报集成必须通过统一的**标准化文件层**完成文本化与结构化，使后续微内容切片与知识抽取与资讯保持一致。标准化层的核心入口为 `inc_document`，其上游为 `resource_*` 与 `minio_file_index`，下游为 `inc_microcontent` 与抽取/对齐流程。

**研报接入标准化层的步骤**：
1) **原始保真**：研报 PDF/网页进入 `resource_report_<source>`，文件索引写入 `minio_file_index`；`resource_file_id` 对应 `minio_file_index.file_id`（SHA-256 内容哈希）；
2) **文本化**：优先读取 PDF 文字层；无文字层则 OCR 生成纯文本（仅文本，不解析图像语义）；
3) **标准化落库**：将清洗后的全文、摘要、标题与元数据写入 `inc_document`，并保留 `resource_doc_id/resource_file_id` 追溯；`standard_content` 采用 Markdown 格式，补充 `content_format/content_structure` 便于质量校验；
4) **类型扩展**：在 `inc_document` 里用 `resource_type=report` 标识研报类型，研报特有字段写入扩展字段（如 `report_type/institution/analyst/rating/target_price/report_date/forecast_horizon`）；
5) **统一下游**：微内容切片、实体/关系抽取、对齐与入库均从 `inc_document` 进入，确保与资讯一致。

**标准化层的关键约束**：
- 研报必须进入 `inc_document` 后才允许进入抽取环节；
- 任何新增文档类型只允许在“解析/清洗/扩展字段”处差异化，**不改变** `inc_document` 主结构；
- `resource_doc_id / resource_file_id / process_batch_id` 必须贯穿后续链路以保证可追溯性。

## 4. 全流程处理链路

1) **接入与保真（资源层）**
- 研报多为 PDF/网页，统一登记 `ds_basic_info`，配置 `ds_access_task`，执行记录写入 `ds_access_record`；
- 原始文件进入 `minio_file_index`，原始记录进入 `resource_report_<source>`。

2) **文本解析（资源层）**
- 提取 PDF 文字层；对扫描件进行 OCR 生成文本；
- 不解析图片/图表含义，仅保真存储。

3) **贴源明细（资源层）**
- 标准化文本写入 `inc_document`（标准化文件层核心入口）；
- 研报元数据写入扩展字段（机构、作者、评级、目标价、报告期等）。

4) **语义抽取（要素层前置）**
- LLM+规则抽取：评级、目标价、预测指标、关键假设、风险提示等；
- 表格文本按行/列解析为结构化字段。

5) **本体对齐与ID映射（本体模型库驱动）**
- 映射到 `ResearchReport` 及相关属性/关系；
- 实体消歧与全局 ID 绑定。

6) **知识沉淀（实例知识库）**
- 写入 `entity_instances / inc_statement / inc_context`；
- 同步生成 `standard_document / micro_document`（由 `inc_document / inc_microcontent` 派生）；
- `inc_context` 存证据、时间范围、来源与抽取方式。

7) **索引与推理（服务层）**
- ES 索引文档、实体与 Statement；
- 图谱与向量索引更新。

8) **反馈闭环**
- 人工审核与规则修订回写 `inc_context/inc_statement`；
- 本体版本更新触发映射规则刷新。

## 5. 与库表设计的对齐说明

严格对齐《产业网链数据海平台库表设计文档》：
- **资源层**：`ds_basic_info / ds_access_task / ds_access_record / resource_* / minio_file_index / inc_document / inc_microcontent`；
- **要素层**：`inc_ontology_* / standard_document / micro_document / entity_instances / inc_statement / inc_context / confidence_rules`；
- **分析层**：`indicator_dictionary / indicator_ontology_mappings / entity_id_mappings / dwd_entity_fact`。

研报重点映射原则：
1) 研报文档统一进入 `inc_document`；
2) 研报事实进入 `inc_statement`，证据进入 `inc_context`；
3) 量化指标优先入仓；
4) **仅处理文本知识**，不解析图表与图片含义。
5) 知识网络展示使用 `standard_document / micro_document`，与 `inc_document / inc_microcontent` 通过 `doc_id` 关联。

## 6. 研报来源与接入说明（爬取与合规）

本方案默认研报来源以**公开可访问渠道**或**已授权渠道**为前提，接入方式如下：
- **数据源登记**：所有来源先登记 `ds_basic_info`；
- **接入任务**：按来源配置 `ds_access_task`，记录 `ds_access_record`；

## 9. 原型验证清单与验收标准

**验证清单（最小闭环）**
- 研报接入后生成 `doc_id` 且可去重；
- 研报文本可抽取关键指标并落库；
- Context 提供证据与时间上下文；
- ES/图谱/向量索引可检索；
- 可追溯链路完整：研报 → 实体/事实 → 指标。

**验收标准（建议）**
- 抽取准确率 ≥ 0.8（人工抽样）；
- 去重准确率 ≥ 0.9（doc_id/标题相似度抽样）；
- 单条研报从接入到检索可用 ≤ 30 分钟；
- 关键字段完整率 ≥ 95%（doc_id/report_date/institution/statement_id）。

## 10. 风险与注意事项

- **版权与合规**：研报版权限制需严格遵守；
- **多版本冲突**：同机构多次更新需版本化管理；
- **Statement 膨胀**：需控制抽取范围并做冷热分层；
- **图像不解析**：图表/图片仅保真，避免误抽取。
