# 🛠️ 运维脚本使用说明

`backend/scripts/` 目录下的运维工具脚本使用指南。

---

## 📋 脚本概览

|               脚本               |    用途     |   使用场景    |
|--------------------------------|-----------|-----------|
| `init_sources.py`              | 初始化数据源可信度 | 首次部署      |
| `backfill_momentum_history.py` | 回填历史动量数据  | 数据迁移/算法调整 |
| `create_indexes.py`            | 创建数据库索引   | 性能优化      |
| `check_code_integrity.py`      | 代码完整性检查   | 开发调试      |

---

## 1️⃣ 数据源初始化 - init_sources.py

**用途**: 预填充10个权威数据源（新华社、财新网、36氪等）到 MongoDB，为动量计算提供可信度基准。

**使用方法**:

```bash
docker exec -it zhilian-backend python /app/scripts/init_sources.py
```

**预置数据源**: 新华社(0.95)、人民日报(0.95)、财新网(0.9)、第一财经(0.88)、36氪(0.8)、虎嗅网(0.75)、知乎(0.4)、微博(0.3)等

**注意事项**:
- 已存在的数据源会自动更新
- 可信度分数影响动量计算权重
- 可编辑脚本自定义数据源

---

## 2️⃣ 历史动量回填 - backfill_momentum_history.py

**用途**: 回溯计算历史动量数据，为实体补充历史记录，支持时间轴趋势分析。

**使用方法**:

```bash
# 回填最近30天（推荐）
docker exec zhilian-backend python /app/scripts/backfill_momentum_history.py --days 30

# 回填最近7天（快速测试）
docker exec zhilian-backend python /app/scripts/backfill_momentum_history.py --days 7
```

**执行时长**: 1000个实体 × 30天 ≈ 3-5分钟

**⚠️ 重要提示**:
- 会清空现有的历史记录
- 需要有足够的历史文档数据
- 建议在低峰期执行
- 执行前建议备份数据库

## 3️⃣ 数据库索引创建脚本

### 📄 文件名

`create_indexes.py`

### 🎯 用途

为 MongoDB 集合创建索引，显著提升查询性能。

### 📊 创建的索引

#### crawled_articles（文章集合）

- `idx_crawled_at_desc` - 按爬取时间降序（分页查询）
- `idx_processed` - 按处理状态查询（筛选未处理文章）
- `idx_processed_crawled_at` - 复合索引（处理状态 + 时间）
- `idx_url` - URL索引（去重查询）

#### canonical_entities（实体集合）

- `idx_current_momentum_desc` - 按动量值降序（动量排行榜）
- `idx_type_momentum` - 复合索引（类型 + 动量，分类排行）
- `idx_last_updated_desc` - 按更新时间降序（最近更新）
- `idx_names` - 实体名称索引（搜索功能）

#### document_instances（文档实例集合）

- `idx_created_at_desc` - 按创建时间降序（时间轴）
- `idx_entity_references` - 实体引用索引（情报溯源）
- `idx_entity_created_at` - 复合索引（实体 + 时间，时间轴查询）

#### task_history（任务历史集合）

- `idx_started_at_desc` - 按开始时间降序（任务列表）
- `idx_task_name` - 任务名称索引（筛选特定任务）

### 💡 使用方法

```bash
# 在容器中执行
docker exec zhilian-backend sh -c "cd /app && PYTHONPATH=/app python scripts/create_indexes.py"
```

### ⏱️ 执行时长

- **首次执行**: 20-30秒（取决于数据量）
- **重复执行**: < 5秒（索引已存在会自动跳过）

### 📈 性能提升

|  查询类型  |            无索引            | 有索引  |  性能提升   |
|--------|---------------------------|------|---------|
| 动量排行榜  | 800ms                     | 15ms | **53倍** |
| 时间轴查询  | 1200ms                    | 25ms | **48倍** |
| 文章列表分页 | 600ms                     | 10ms | **60倍** |
| 实体搜索   | 150优化 - create_indexes.py |

**用途**: 为 MongoDB 集合创建索引，大幅提升查询性能（50倍+）。

**使用方法**:

```bash
docker exec -it zhilian-backend python /app/scripts/create_indexes.py
```

**创建的索引**:
- **crawled_articles**: 时间、处理状态、URL索引
- **canonical_entities**: 动量排序、类型分类、名称搜索索引
- **document_instances**: 时间轴、实体引用索引
- **task_history**: 任务名称、时间索引

**注意事项**:
- 索引已存在会自动跳过
- 首次执行需20-30秒
- 查询速度提升50倍以上

## 💡 最佳实践

1. ✅ **首次部署时先创建索引** - 避免后期数据量大时创建缓慢
2. ✅ **定期（每季度）审核数据源可信度** - 保持评分准确性
3. ✅ **调整算法后重新回填历史** - 确保历史数据一致性
4. ✅ **在低峰期执行耗时脚本** - 避免影响用户体验
5. ✅ **执行前备份数据库** - 特别是 backfill 操作

### 常见问题

**Q: 提示 "No module named 'app'"**  
A: 确保在容器中执行，不是宿主机

**Q: backfill 执行很慢**  
A: 减少回溯天数或在低峰期执行

**Q: 索引提示已存在**  
A: 正常现象，会自动跳过
