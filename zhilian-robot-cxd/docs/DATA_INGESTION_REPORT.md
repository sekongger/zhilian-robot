
## 1. 概述

本报告详细介绍了智链机器人项目中**数据接入与初加工模块**的设计与实现。该模块实现了从原始数据到 MongoDB 和 MinIO 的完整存储流程，为后续的 NLP 分析和知识图谱构建提供高质量的数据基础。

### 1.1 模块目标

- **统一数据接入** - 支持多种数据源格式（文件、API、流式数据）
- **数据清洗与标准化** - 提升数据质量，消除噪声
- **去重处理** - 避免存储冗余数据
- **大数据存储** - 原始文件存储到 MinIO，元数据存储到 MongoDB

### 1.2 技术栈

| 组件 | 技术选型 | 用途 |
|------|---------|------|
| 对象存储 | MinIO | S3 兼容的原始文件存储 |
| 文档数据库 | MongoDB 8.0 | 元数据和结构化数据存储 |
| 后端框架 | FastAPI | RESTful API 服务 |
| 文件解析 | PyPDF2, pdfplumber, openpyxl, python-docx | 多格式文件解析 |
| 去重算法 | SimHash | 近似文本去重 |

## 3. 数据接入层


### 3.1 文件接入器 (FileIngestor)

支持的文件格式：

| 格式 | 扩展名 | 解析库 | 功能 |
|------|--------|--------|------|
| PDF | .pdf | PyPDF2, pdfplumber | 文本提取、表格提取 |
| Excel | .xlsx, .xls | pandas, openpyxl | 多 Sheet 读取 |
| CSV | .csv | pandas | 自动编码检测 |
| Word | .docx | python-docx | 段落和表格提取 |
| 文本 | .txt, .json, .xml | 原生 | 直接读取 |

**使用示例**:

```python
from app.ingestion import FileIngestor

# 创建接入器
ingestor = FileIngestor(source_name="report_upload")

# 接入文件
records = ingestor.ingest("/path/to/file.pdf")

# 验证并存储
for record in records:
    if ingestor.validate(record):
        record.extracted_text = ingestor.extract_text(record)
        ingestor.save_to_storage(record)    # MinIO
        ingestor.save_metadata(record)      # MongoDB
```

## 4. 数据清洗层

### 4.1 DataCleaner (数据清洗器)

**主要功能**:

| 方法 | 功能 | 示例 |
|------|------|------|
| `clean_html()` | 移除 HTML 标签，提取纯文本 | `<p>文本</p>` → `文本` |
| `clean_text()` | 规范化空白、移除控制字符 | `多个   空格` → `多个 空格` |
| `remove_boilerplate()` | 移除样板文本（版权、广告等） | `版权所有...` → `` |
| `fix_encoding()` | 修复编码问题 | GBK/UTF-8 自动检测 |

**样板文本匹配规则**:
- 版权声明: `版权所有.*?保留.*?权利`
- 编辑信息: `责任编辑[:：].*`
- 来源标注: `来源[:：]\s*(新华社|中新网).*`
- 社交媒体: `关注.*?公众号.*`, `扫.*?二维码.*`

### 4.2 DataNormalizer (数据标准化器)

**日期标准化**:

| 输入格式 | 处理方式 |
|---------|---------|
| `3小时前`, `昨天` | 相对时间计算 |
| `Dec 15, 2024` | 中文日期解析 |
| 今天/昨天/本周 | 关键词映射 |

**公司名称标准化**:
- 移除后缀: `股份有限公司`, `Co., Ltd.` 等

## 5. 存储层

本系统采用**双存储架构**：MinIO 负责存储原始二进制文件，MongoDB 负责存储结构化元数据。两者协同工作，实现高效的数据管理和检索。

### 5.1 MinIO vs MongoDB 存储对比

| 维度 | MinIO | MongoDB |
|------|-------|---------|
| **存储类型** | 对象存储（二进制文件） | 文档存储（结构化JSON） |
| **存储内容** | 原始文件（PDF/Excel/图片等） | 元数据、提取的文本、处理状态 |
| **数据大小** | 大文件（MB～GB级别） | 小数据（KB级别） |
| **查询能力** | 仅支持按路径访问 | 支持复杂查询和索引 |
| **访问方式** | S3 API / 预签名URL | MongoDB Driver |
| **主要用途** | 长期归档、原始数据备份 | 快速检索、业务逻辑处理 |

### 5.2 MinIO 对象存储

#### 存储内容

MinIO 存储**原始二进制文件**，保持数据的完整性和可追溯性：

| 数据类型 | 说明 | 示例 |
|---------|------|------|
| 原始 PDF | 用户上传的 PDF 文件原件 | `industry_report.pdf` |
| Excel 表格 | 产业数据表格原件 | `company_list.xlsx` |
| 爬虫网页 | 网页 HTML 快照 | `news_page.html` |
| 图片附件 | 文档中的图片 | `chart.png` |

#### 存储结构

```
raw-data/                              # 原始数据桶
├── file/                             # 文件上传来源
│   └── 2026/01/26/                  # 按日期分区
│       ├── a1b2c3d4_report.pdf      # {hash}_{原文件名}
│       └── e5f6g7h8_data.xlsx
├── rss/                              # RSS 订阅来源
│   └── 2026/01/26/
│       └── 36kr_article_001.html
└── crawler/                          # 爬虫来源
    └── 2026/01/26/
        └── baidu_news_002.html

processed-data/                        # 处理后数据桶
└── nlp_results/                      # NLP 处理结果
    └── 2026/01/26/
        └── a1b2c3d4_entities.json   # 提取的实体JSON
```

#### 后续使用场景

| 使用场景 | 说明 |
|---------|------|
| **数据溯源** | 当 NLP 提取结果有疑问时，可回溯原始文件进行人工核验 |
| **重新处理** | 算法升级后，可从 MinIO 取出原文件重新执行 NLP 处理 |
| **合规审计** | 保留原始数据用于数据来源证明和合规检查 |
| **文件下载** | 用户可通过预签名 URL 直接下载原始文件 |

#### 配置参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| MINIO_ENDPOINT | minio:9000 | 服务地址 |
| MINIO_ACCESS_KEY | admin | 访问密钥 |
| MINIO_SECRET_KEY | password123 | 密钥 |
| MINIO_BUCKET_RAW | raw-data | 原始数据桶 |
| MINIO_BUCKET_PROCESSED | processed-data | 处理后数据桶 |

### 5.3 MongoDB 元数据存储

#### 存储内容

MongoDB 存储**结构化元数据和提取的文本**，支持快速查询和业务处理：

| 数据类型 | 说明 | 用途 |
|---------|------|------|
| 记录 ID | 唯一标识符 | 关联 MinIO 文件 |
| 来源信息 | 数据源类型、名称、URL | 数据分类和统计 |
| 提取文本 | 从文件中提取的纯文本 | NLP 处理输入 |
| 文件元数据 | 文件名、大小、类型 | 文件管理 |
| MinIO 路径 | 对象存储路径 | 关联原始文件 |
| 处理状态 | 是否已 NLP 处理 | 任务调度 |
| 提取实体 | NLP 提取的实体列表 | 知识图谱构建 |
