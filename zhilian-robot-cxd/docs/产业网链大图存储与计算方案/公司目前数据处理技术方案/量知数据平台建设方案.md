# 量知数据平台建设方案

# 一、背景与目标

## 1.1建设背景

        为了满足量知数据业务发展，一方面是接入的数据越来越多，数据源接入方式也根据数据提供方因人而异，数据源格式也参差不齐。当前欠缺一套比较完善的数据接入策略，保障数据接入的高效性及准确性。

        另一方面是当前存储的数据类目越来越多、数据结构越来越杂、数据数量越来越大。以往小数据量场景下的mongo、es、mysql等数据库选型混用的场景未暴露的问题，在大数据大体量、复杂结构的冲击下逐一暴露出来。部分数据生产场景由于读写的困难，甚至不得不抛弃原有的生产逻辑，单独开辟存储位置支撑线上业务。这对于数据库的管理、数据资源的使用均会造成极大的负担。因此急需结合各类数据库选型的特征，重新规划调整数据存储方案，确保数据的管理和使用在无障碍的场景下进行。

        通过建设量知数据内部数据平台，整合企业内外部数据资源，提升数据采集、治理、加工能力，为数据生产、数据资产化提供强有力的支持。

## 1.2建设目标

        产业大数据具有数据规模大、多源异构、数据处理过程复杂冗长、数据服务多样等特点。因此需要构建大数据平台以满足日益增长和复杂的需求：

● 支持海量数据规模处理：亿级数据规模

● 支持多源异构数据源接入：文件、数据API、数据库等来源以及结构化、半结构化、非结构化数据

● 支持复杂的数据治理过程：包括数据清洗、关联计算、知识抽取等数据治理过程

● 支持高效的数据运营工作：支持人工在平台上对数据质量进行运营

● 支持高效复杂的数据关联分析和取数：支持表深度关联分析以及快速取数

● 支持友好的数据可视化：支持无代码的数据展示和分析

### 2.5.3数据编目

数据编目是指对数据资源进行分类、组织和管理的过程。它涉及到对数据的收集、整理、分类、编目、检索和利用等方面。以下是对数据编目的方式进行详细阐述：

*   数据分类：数据分类是数据编目的第一步，它是对数据进行归类和定义的过程。根据数据类型和性质，可以采用不同的分类方法，如主题分类、学科分类、主题词表分类等。分类方式的选择应该根据数据的特点和需求来确定。
    
*   数据组织：数据组织是将数据按照一定的结构进行排列和组织，以便于数据的存储、管理和检索。数据组织的方式可以根据数据的类型和规模来选择，如文件系统、数据库系统、分布式系统等。
    
*   数据描述：数据描述是对数据进行描述的元信息，包括数据的名称、标识符、来源、时间、类型、格式、大小等。这些信息可以帮助用户更好地理解数据，并方便地找到所需的数据资源。
    
*   数据索引：数据索引是对数据进行组织和检索的一种方式，它可以根据数据的特征和需求，建立相应的索引结构，如倒排索引、树状索引等。通过索引，可以快速地查找到所需的数据资源。
    
*   数据检索：数据检索是利用数据编目后的结果，通过一定的搜索方式和方法，查找和获取所需的数据资源。数据检索的方式可以根据数据类型和规模来选择，如关键词检索、全文检索、基于内容的检索等。
    
*   数据管理：数据管理是对数据进行维护、更新、备份和恢复等操作的过程。它涉及到数据的完整性、一致性和安全性等方面的管理，以确保数据的可靠性和可用性。
    

数据编目模块提供对数据资产的编目管理，用户通过平台提供的数据资产编目管理能力，能够快速创建不同数据资产的分类目录，可以有效整合数据资产，完成编目管理工作，为后续的数据使用以及数据共享等相关数据工作提供坚实的数据基础。

## 2.7 数据标准体系

在数据开发过程中，数据标准是至关重要的环节，它涉及数据的收集、处理、存储、分析和应用等多个方面。

（1）数据建模标准：

*   选择合适的建模方法，如维度建模或规范化建模，根据业务需求和数据特征确定最佳的数据模型。
    
*   规范数据模型的设计和管理，确保数据的一致性和可维护性。采用统一的数据建模方法和建模工具，减少数据冗余和不一致性。
    

（2）数据质量标准：

*   制定数据质量管理流程和数据质量指标，包括数据的准确性、完整性、一致性和及时性等。
    
*   设定数据清洗和验证的规则，以确保数据的质量符合标准。在数据抽取、转换和加载过程中，应用这些规则对数据进行质量检测和清洗。
    

（3）数据集成标准：

*   确定数据集成的方法和技术，如ETL（提取、转换、加载）工具或数据仓库中间件等。
    
*   制定数据交换和共享的规则，确保不同系统之间的数据能够高效、安全地集成和交换。
    

（4）数据安全标准：

*   建立完善的数据安全管理体系和安全策略，包括数据加密、访问控制、审计和备份等。
    
*   确保数据的机密性、完整性和可用性，防止数据泄露、篡改或丢失。
    

## 2.8 数据安全体系

数据安全治理是指在数据的处理过程中，包括数据的收集、存储、加工、传输、提供、公开等环节，对数据采取必要的措施，确保数据处于有效保护和合法利用的状态。以数据为中心，从数据的全生命周期角度开展数据安全管理工作，包括用户管理、登录认证、授权鉴权、传输加密、数据脱敏、分级分类、操作审计、安全响应等工作。数据安全体系需要对产业数据制定统一的数据安全策略与规程，主要包括以下关键环节：

1、数据安全标准

收集整合数据安全的相关标准以及产业数据的相关标准，如《公共数据开放与安全管理细则》、《公共数据分类分级规范》、《公共数据管理办法》《信息安全技术 数据安全能力成熟度模型》等国家、行业的数据安全标准，结合产业大数据特点，制定更加详细的数据安全标准，如权限管理、数据授权流程、数据分级分类、安全管理措施等。

2、数据分级分类

根据产业数据的重要性和敏感程度，对数据进行分类分级，并制定相应的保护措施。

按照产业数据一旦遭到篡改、破坏、泄露或者非法获取、非法利用，对个人、组织合法权益造成的危害程度，将一般数据从低到高分为1级、2级、3级、4级共四个级别。

1级数据具有公共传播属性，可对外公开发布、转发传播，但也需考虑公开的数据量及类别，避免由于类别较多或者数量过大被用于关联分析。

2级数据通常在组织内部、关联方共享和使用，相关方授权后可向组织外部共享。

3级数据仅能由授权的内部机构或人员访问，如果要将数据共享到外部，需要满足相关条件并获得相关方的授权。

4级数据按照批准的授权列表严格管理，仅能在受控范围内经过严格审批、评估后才可共享或传播。

（1）数据安全规则

结合数据安全标准，制定数据安全规则，后续将由数据安全引擎进行规则的执行。具体包括安全规则的制定、查询、修改等功能。

（2）数据安全引擎

权限管理：根据数据分级分类结果，以及数据应用场景，制定不同数据资源的不同角色不同岗位的数据权限，包括查看、下载、修改、删除、分享等操作。

数据脱敏：对于敏感的数据或者是字段，需要进行数据脱敏，如隐藏、截断、转换等方式。

数据加密：对于重要的数据需要进行加密，如增加密码、格式转换等方式。

风险监控：持续监控数据资源的增删改查等操作，对于异常操作或者是潜在风险操作，系统及时发出警告，并主动制止。

（3）数据安全审计

定期通过对用户访问数据库行为的记录、分析和汇报，来帮助用户事后生成合规报告、事故追根溯源，同时通过大数据搜索技术提供高效查询审计报告，定位事件原因，以便日后查询、分析、过滤，实现加强内外部数据库网络行为的监控与审计，提高数据资产安全。

最后需要构建全生命周期纵深防御体系：从数据的产生、存储、传输、使用、共享、销毁等全生命周期进行保护，确保每个环节的安全，加强数据安全风险防控：通过定期进行风险评估，识别和评估潜在的数据安全风险，并采取相应的措施进行防控。同时建立数据安全应急预案：针对可能的数据安全事件，制定应急预案，明确应急处置流程和责任人。

# 三、数据平台建设现状

![image](https://alidocs.oss-cn-zhangjiakou.aliyuncs.com/res/J9LnWNyPyJ45lvDe/img/05c4aadc-1611-4aaa-8b66-c6c2da753031.png)

**数据存储**

存在问题点：

1、目前数据存储形式较多Mysql、MongoDB、ES、Doris、Reids、OSS，数据较为分散，ODS层是否接入Hudi，将结构化、半结构化、非结构化文件进行统一存储。

2、需要考虑数据融合，涉及多方数据来源进行数据融合，目前仅Doris聚合模型在一定程度实现数据的融合，支持Max、Min，SUM、Replace等函数。

3、Doris目前2.0版本支持倒排索引等相关功能，但处于初始版本，问题可能较多，后续等稳定后接入使用。

**数据计算**

当前没有采用基于其他处理引擎，纯python代码进行开发，常用库包涵盖request、pandas、DorisClient、pymysql、pymongo、elasticsearch等。

存在的问题点：

1、当前的etl流程是基于纯Python脚本开发，开发模式较为笨重，相较于sql层面开发，开发时间长，流程复杂，效率较低，数据实时性较差。

2、当前是基于Doris搭建的数仓，对于大宽表，数量达到亿级别，单表字段数量超过一百多个，涉及的一些关联查询及模糊查询或者等值查询效率较低。列式存储数据自身的存储架构导致在取所有列是通过遍历拼接的方式，当数据列较多，查询数据较慢。

3、大表数据join查询性能较慢。

4、数据传输稳定性，之前海关数据es同步到doris经常出现节点挂掉。

5、Doris生态还不太完善，与spark兼容性还存在一些问题，会踩一些坑，使用过程存在一定的问题，大数据传输存在节点挂掉，原因排查困难。

**数据管理**

存在的问题点：

1、涉及的数据模块较为分散，（数据存储、数据计算、数据治理与应用）没有的较好的平台进行统一集成，缺乏数据统一管理，监控。

2、目前为了满足业务发展是“重数据采集、处理，轻数据质量”，对于最终的结果数据缺乏对应的量化质量标准，导致最终的数据应用和项目交付存在隐形成本和用户投诉。

**解决方案：**

1、引入Spark处理引擎将笨重的代码开发模式转变成sql开发模式。

2、Doris全字段查询慢。目前测试专利表数据量近亿，通过分桶字段进行查询，查询时间可控制8分钟内，导出数据量约1.8G，导出时间10分钟，单表多字段查询问题及导出问题可接受。

3、大表join较慢。采用colocation join进行优化，目前正在测试中。

4、大数据量同步传输不稳定。采用Spark等其他数据同步工具进行测试。

6、Doris服务节点挂接问题，重新测试继续排查节点挂掉原因。同时，采用supervisor自动拉起服务。
