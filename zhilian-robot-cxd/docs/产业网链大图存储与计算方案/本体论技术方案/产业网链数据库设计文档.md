# 产业网链数据库设计文档（智链机器人实证版）

## 一、概述

本文档基于《本体论指导下的产业数据平台技术方案》，结合智链机器人现有的数据采集与NLP处理能力，设计**轻量化、可验证**的数据库方案。

**设计原则**：
- **简化分层**：从传统5层数仓简化为3层，聚焦本体语义而非数仓分层
- **统一前缀**：本体核心表统一使用 `inc_` 前缀（Industry Chain）
- **最小数据集**：优先选择机器人产业链数据进行端到端验证
- **复用现有能力**：对接智链机器人的 Neo4j/MongoDB/LLM 处理链路

## 三、简化分层架构

### 3.1 三层架构设计

**简化理由**：本体论强调的是**语义统一**而非数仓分层，实证阶段无需复杂的维度建模。

```
┌─────────────────────────────────────────────────────────────────┐
│                      服务层（Service）                           │
│   Action执行引擎 + 图谱查询API + 语义检索                         │
│   技术栈：FastAPI + Neo4j Cypher + (可选)Milvus                  │
├─────────────────────────────────────────────────────────────────┤
│                      本体层（Ontology）                          │
│   MySQL（inc_* 本体元数据表） + Neo4j（实体+关系图谱）             │
│   核心：类定义、属性定义、关系定义、实例注册                        │
├─────────────────────────────────────────────────────────────────┤
│                      接入层（Ingest）                            │
│   MongoDB（采集原始JSON + 规范实体） + MinIO（原始文件）           │
│   核心：数据采集、NLP处理、本体标签标注                            │
└─────────────────────────────────────────────────────────────────┘
```

### 3.2 与传统数仓分层对比

| 传统数仓 | 本方案 | 简化说明 |
|---------|-------|---------|
| RAW（原始层） | 接入层 | 合并，MongoDB统一存储原始数据 |
| ODS（贴源层） | 接入层 | 合并，NLP处理后直接标注本体标签 |
| DW（仓库层） | 本体层 | 简化为本体元数据表+图数据库 |
| DM（集市层） | - | **省略**，实证阶段不需要主题宽表 |
| ADS（应用层） | 服务层 | 直接通过Action提供服务 |

### 3.3 数据库实例规划（精简版）

| 数据库类型 | 实例名 | 存储内容 | 实证容量 |
|-----------|-------|---------|---------|
| **MySQL** | `inc_ontology` | 本体元数据（inc_* 表） | 100MB |
| **Neo4j** | `industry_graph` | 产业知识图谱（节点+关系） | 1GB |
| **MongoDB** | `industry_doc` | 采集原始数据 + 规范实体 + 动量数据 | 5GB |
| **Redis** | `industry_cache` | 热点缓存、Celery任务队列 | 500MB |
| **MinIO** | `industry_file` | 原始PDF/图片（可选） | 10GB |

**后续扩展**：
- 数据量增长后可增加 ES（全文检索）
- 需要语义检索时增加 Milvus（向量库）

```sql
    INDEX idx_class_id (class_id),
    INDEX idx_canonical_name (canonical_name)
) COMMENT='实例注册表';
```

**说明**：此表与 Neo4j 图数据库节点一一对应，用于：
1. 实体去重与规范化（通过 aliases 匹配）
2. 记录引用次数与动量（与智链机器人现有逻辑对接）
3. 支持实体状态管理（合并、废弃）

## 七、数据流转与ETL设计

### 7.1 简化ETL流程

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│   数据采集   │ ──▶ │   NLP处理   │ ──▶ │  本体标注   │ ──▶ │  图谱写入   │
│  RSS/爬虫   │     │ DeepSeek LLM│     │ inc_*表查询 │     │ Neo4j/MySQL │
└─────────────┘     └─────────────┘     └─────────────┘     └─────────────┘
       │                   │                   │                   │
       ▼                   ▼                   ▼                   ▼
   MongoDB            MongoDB            inc_instance         Neo4j节点
 (raw_documents)  (document_instances)   (实例注册)           + 关系边
```

### 7.2 本体标注逻辑

NLP处理完成后，增加本体标注步骤：

```python
def annotate_ontology(entities: Dict, relations: List[Dict]) -> Dict:
    """
    对NLP抽取结果进行本体标注
    """
    annotated_entities = []
    for category, items in entities.items():
        # 查询 inc_class 获取类定义
        class_info = query_inc_class(category)
        for item_name in items:
            # 查询或创建 inc_instance
            instance = get_or_create_instance(
                class_id=class_info['class_id'],
                canonical_name=item_name
            )
            annotated_entities.append({
                'instance_id': instance['instance_id'],
                'class_id': class_info['class_id'],
                'name': item_name,
                'category': class_info['category']
            })
    
    annotated_relations = []
    for rel in relations:
        # 查询 inc_relation 获取关系定义
        rel_type = query_inc_relation(rel['relation'])
        annotated_relations.append({
            'relation_id': rel_type['relation_id'],
            'source_instance_id': find_instance(rel['subject']),
            'target_instance_id': find_instance(rel['object']),
            'confidence': rel.get('confidence', 0.9)
        })
    
    return {
        'entities': annotated_entities,
        'relations': annotated_relations
    }
```

### 8.2 Action示例（股权穿透）

```python
def equity_penetration(enterprise_id: str, depth: int = 3) -> List[Dict]:
    """
    股权穿透Action
    
    输入：企业instance_id, 穿透深度
    输出：股权路径列表
    """
    query = f"""
    MATCH path = (e:Enterprise {{instance_id: $enterprise_id}})-[:INVEST*1..{depth}]-(related:Enterprise)
    RETURN path, 
           [r IN relationships(path) | r.ratio] as ratios,
           [n IN nodes(path) | n.name] as names
    LIMIT 100
    """
    results = neo4j.execute_query(query, {"enterprise_id": enterprise_id})
    return format_equity_paths(results)
```

## 十一、总结

本设计文档针对**智链机器人实证**场景，做了以下简化：

1. **架构简化**：5层数仓 → 3层架构（接入层+本体层+服务层）
2. **表结构统一**：使用 `inc_` 前缀，设计6张核心本体表
3. **数据精简**：聚焦机器人产业链，50家企业+200条关系即可验证
4. **对接现有**：复用智链机器人的 Neo4j/MongoDB/LLM 链路

核心价值：用**最小数据集**验证**本体论驱动**的完整数据流，为后续产业网链大图建设奠定基础。
